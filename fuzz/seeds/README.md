# Fuzz seeds

Per-target seed corpora. **Everything committed here is a synthetic fixture**,
built by `cargo run -p lightcraft-fuzz --bin gen-seeds --` from the same
sample streams the `crx.rs` / `meta/cr3.rs` unit tests construct — original
work, no third-party material, no real photographs or camera metadata.

```bash
cargo run -p lightcraft-fuzz --bin gen-seeds -- --samples "D:\path\to\CR3s"
```

## Licensing note (important)

Real photos and real header slices are **never committed**: the first 64 KiB of
a CR3 contains the Canon `uuid` box with `CMT1–CMT4` TIFF blocks — maker-note
metadata that can carry the camera's serial number and owner settings. If you
regenerate seeds from your own files, keep both the full files and any
header slices outside the repository (the root `.gitignore`'s corpus policy
covers them) and run the mutation harness against them locally. Linux CI
fuzzes full real files from `cargo xtask corpus --download` (CC0, pinned by
SHA-256) instead. All files here are synthetic fixtures generated by
`gen-seeds` from code in this repository (MIT OR Apache-2.0, same as the
project).

## cr3_container/ — raw-byte container fuzzing

| File | What it is |
|---|---|
| `container-synthetic.bin` | Minimal CR3: Canon uuid with CMT1/CMT2/CMT4 TIFFs + THMB, JPEG track, raw track with a deliberately malformed 4-byte CMP1, XMP uuid box (~4.2 KiB). |
| `container-crx-lossless.bin` | Same wrapper, but the raw track is a valid 4×4 lossless CRX sample — decodes end to end. |

## crx_bitstream/ — structure-aware CRX payload fuzzing

Each seed is `[selector byte][CRX sample payload]`; the harness builds a valid
container with a capped CMP1 descriptor from the selector. The payloads are the
synthetic sample streams from the `crx.rs` unit tests (lossless flat, 16×16
three-level C-RAW, 16×16 v0x200 adaptive QP, 64×48 two-tile lossless header,
and the C-RAW clamp-overshoot variant). Seeds named `crx-lossless-4x4`,
`crx-craw-16x16`, `crx-v200-qp-16x16` and `crx-craw-clamp-16x16` decode fully;
`crx-lossless-two-tile-64x48` passes the header walk (`probe_info`) and its
truncated entropy data exercises the decode-failure path.

## cr3_whole_file/ — whole-file mutation fuzzing

| File | What it is |
|---|---|
| `container-synthetic.bin`, `container-crx-lossless.bin` | Full synthetic CR3 containers (same bytes as the cr3_container seeds) — small enough to mutate exhaustively. |
| *(not committed)* | **Full** real CR3 files stay outside the repository. Point the harness at them locally (a private directory of real CR3s). Linux CI fuzzes full files from `cargo xtask corpus --download` (CC0, pinned by SHA-256) instead. |

## iso_bmff_boxes/ — structure-aware box-graph fuzzing

| File | What it is |
|---|---|
| `boxes-consistent.bin` | A synthetic box graph with consistent sizes. |
| `boxes-size-lie.bin` | The same graph with the `moov` size field lying (+4). |
| *(live corpus)* | The generator needs no seeds to be productive; these anchor its consistent-path behaviour. |

## Hygiene

- After any crash: minimize (`cargo fuzz tmin <target> <artifact>` locally, or
  `-minimize_crash=1`), then commit the minimized input **here** (it becomes a
  permanent regression seed) and record it in `../FINDINGS.md`.
- Keep seeds small (KiB, not MiB). `cargo fuzz cmin <target>` trims the live
  corpus weekly; committed seeds are curated by hand.
